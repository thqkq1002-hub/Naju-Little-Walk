# 전망대 고저차 보강 v96

사용자의 ‘나무 전망대’는 프로젝트의 빛가람 전망대로 해석했다. 확인 질문을 남겼으며 다른 장소라는 답변은 아직 없었다. 작업 브랜치는 `codex/bitgaram-place-walks`다. 기본 `main`에는 두 장소의 최신 모델이 없어 해당 작업 브랜치를 사용했다.

## 지도와 사진 대조

- 느러지 기준 좌표: OSM 전망대 노드 6572786690, 34.9159348 / 126.5419381. [OSM](https://www.openstreetmap.org/node/6572786690).
- 기존 Copernicus GLO-30 위치 표고 45.7637m, 기존 지면 해석 37.7637m. 수관을 일괄 8m 차감한 수치였고 현장 측량 근거는 없었다.
- [AWS Terrain Tiles](https://registry.opendata.aws/terrain-tiles/) Terrarium 별도 자료에서 같은 위치는 45.6681m였다. 두 제품의 높이가 일치한다는 사실은 8m 차감을 확정하지 못한다. 이번에는 근거리 지형과 전망대·식재·길에서 차감을 철회해 45.7637m를 **새 지면 해석**으로 채택했다. DSM과 혼합 DEM의 식생 영향·관측 시기·수직 기준 차이는 남는다. 조사한 표본과 타일 SHA-256은 `sources/observatory-relief-v96/independent-terrain.json`에 있다.
- [2024-07-08 직접 방문 사진](https://forme13.tistory.com/3621)의 전망대 외관, 정상 조망, 수국길, 낮은 강변 데크에서 올려다본 전망대를 대조했다. 사진 04·05·06·13·21에서 능선 위 전망대와 강변 사이의 높이 관계를 확인했다. 원본 사진은 `work/`의 조사 자료로만 보관하고 배포에 넣지 않았다. 사진에서 정확한 표고나 계단 치수를 측정했다고 주장하지 않는다.
- 빛가람은 기존 v89 산책 모델이 GLO-30 정상 표면 79.1421m, 로컬 기준 25.5m를 사용해 정상 바닥 y=53.6421m를 이미 구현했다. 그러나 별도 장소 선택 지도에는 옛 가우시안 언덕과 y=16m 정상 바닥이 남아 있었다. [기존 표고 조사](bitgaram-park-terrain-plan-2026-10-03.md)와 [공식 관광공사 안내](https://korean.visitkorea.or.kr/detail/rem_detail.do?con_type=11300&cotid=9bcea016-ebf7-4cec-ae02-4d67ce2d49fe)를 대조했다. 기사에 혼재하는 해발 100m를 근거 없이 적용하지 않았다.

## 구현

| 항목 | 이전 | 적용 |
| --- | ---: | ---: |
| 느러지 지면 / 강 수면 로컬 기준 | 37.7637m | 45.7637m |
| 느러지 정상 데크 | 49.7637m | 57.7637m |
| 느러지 지면부터 정상 데크 높이 | 12m | 12m |
| 빛가람 지도 정상 / 호수 로컬 기준 | 16m | 53.6421m |
| 빛가람 산책 모델 정상 | 53.6421m | 같은 높이 유지 |

느러지는 기존 v95c Blender 수정본을 복원·보존하고 새 파일에서 높이만 보강했다. 전망대·계단·수국길·시설과 가까운 식재를 8m 함께 올렸다. 주변 지형은 반경 280m에서 480m까지 기존 원경으로 부드럽게 연결하며 실제 강 경계에서 22m 안쪽은 수면 높이를 유지하도록 연결했다. 강 메시, 지도 평면 좌표, 전망대 구조 높이, 먼 산은 유지했다. 보행 솔리드·경사 평면의 상수항·도착점·표지·검토 카메라와 경로의 높이를 함께 갱신했다. 사람 눈높이는 1.72m다.

빛가람 지도 언덕은 같은 원래 표고 격자와 시설 주변 지형 해석을 사용한다. 정상 바닥·전망대·전시동·계단·근거리 수목·안내 푯말을 연결했다. 별도 산책 모델과 충돌 JSON은 이미 이 높이를 사용하므로 이번 지도 전용 수정에서 변경하지 않았다. 원경 도시의 평면과 원래 삼각형·재질·아파트 창문은 유지했다. 표시용 좌표 압축의 최대 오차는 25.5mm이며, 보행 모델과 충돌 바닥에 이 압축을 적용하지 않았다.

Blender 수정본:

- `outputs/relief-v96/neureoji-relief-v96.blend`
- `outputs/relief-v96/bitgaram-overview-relief-v96b.blend` — 재질의 원래 정점 색도 유지한 편집본.

원본 v95c SHA-256 `87b1eef38a34ed7421be0667c1a6b70fe2ee3101dcf3fbfc7426c8e42d0f7860`과 v89d SHA-256 `4b6a8a260c999f9cdb0061e221b1f866bbcbeea1c510e3a89ac17f601547d044`를 복원 manifest 및 현재 파일과 대조했다. 사용자 수정본을 생성 스크립트로 덮어쓰지 않았다. GLB와 gzip을 함께 내보내고 앱의 캐시 버전도 갱신했다.

## 검증

- 공통 이동 74개: `node --experimental-strip-types --test tests/world.test.mjs` 통과.
- 느러지 8개: 전체 계단·수국길 왕복, 표시 바닥과 충돌 높이, 정상 눈높이와 조망, 강 내부 지형 제외 검사 통과. Node 기본 힙으로 병렬 실행한 첫 시도는 메모리 한도에 도달했고, 별도 8GiB 힙 실행으로 8개 모두 통과했다.
- 빛가람 지도·기존 지형 11개, 신규 고저차 회귀 3개 통과. 지도 정상과 산책 정상 일치, 세 방향 사면과 원자료 일치 검사 포함.
- TypeScript·정적 빌드 통과. 전체 테스트 스위트를 모두 실행했다고 주장하지 않는다.
- 실제 로컬 브라우저에서 빛가람 지도·확대 조작·느러지 정상 조망을 확인했고 브라우저 오류는 없었다. `outputs/relief-v96/browser-*.png`에 화면을 보관했다.
- 기존과 같은 카메라로 전후 Blender 렌더를 비교했다. 원본 사진·Blender 실행 파일·라이브러리·임시 ZIP·작업본은 `public/` 및 정적 배포 폴더에 넣지 않았다. OSM 출처와 ODbL 안내를 유지했다.

자료의 정밀도는 원래 DEM 수준이다. 새 지면 해석은 현장 측량으로 확정된 지면·시설 표고가 아니다. GitHub 푸시와 공개 사이트 배포는 수행하지 않았다.
