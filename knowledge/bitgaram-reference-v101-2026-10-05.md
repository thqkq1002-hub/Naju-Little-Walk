# 빛가람 전망대 모노레일·접근 계단 — 영상 대조 v101

## 자료를 보고 정정한 부분

이전 모델은 미끄럼틀을 모노레일 가까이에 놓은 추정 곡선으로 표현했다. 이번에는 지리 참조가 있는 위성영상에서 보이는 서쪽 덮개 중심선을 읽고, 덮개 내부의 좁은 계단과 별도로 꺾여 내려가는 목재 계단을 구분했다. 모노레일 평면은 기존 OSM way 508048300을 유지했다.

- 덮개가 있는 돌미끄럼틀: 서쪽 곡선을 추적하고 화강암 U형 홈, 반복 목재 아치, 반투명 상부 덮개, 청록색 측면 패널, 내부 손잡이를 Blender에서 제작했다.
- 덮개 내부 계단: 내려다보는 현장 사진을 기준으로 미끄럼틀 오른쪽(서쪽)에 배치했다.
- 별도 목재 계단: 사진의 세 줄 난간, 금속 기둥 캡, 계단 앞 금속 마감과 꺾이는 계단참을 반영했다. 나무에 가린 연결은 추정이다.
- 모노레일 차량: 흰색 둥근 전·후면, 검은 창 테두리, 창 높이의 주황 띠를 반영했다. 객실 바닥·주행부·미닫이문과 탑승 동작은 유지했다.
- 상·하부 승강장: 영상에서 보이는 타원형 흰 덮개를 기존 승강장 주위에 모델링했다. 치수와 기둥 위치는 추정이다.

## 실제 자료

1. [Esri World Imagery 서비스](https://services.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer): 지리 참조 export 범위와 1200×1200 영상으로 미끄럼틀 덮개와 외부 계단의 보이는 평면을 대조했다. 원본 영상은 `work/bitgaram-v101`에만 보관하며 배포하지 않는다.
2. 같은 서비스의 30cm 표시 단계 메타데이터 조회: **촬영일 2023-04-09**, WV02, Vantor Vivid Advanced, 원자료 해상도 **0.5m**, 표시 샘플 **0.3m**, 원자료 위치 정확도 필드 **5m**. 지도에서 가리키는 좌표가 실측 수준으로 정확하다는 뜻이 아니다. 공개 메타데이터는 `sources/bitgaram/access-v101/satellite-metadata.json`에 보존한다.
3. [2025-03-14 현장 사진](https://kg4973.tistory.com/108): 흰색 둥근 차량, 검은 창과 주황 띠, 돌미끄럼틀 옆 계단, 목재 계단의 난간·금속 마감·사진 촬영 쉼터를 브라우저에서 직접 확인했다. 글에 있는 영업·요금 정보는 앱에 추가하지 않았다.
4. [한국모노레일 설치 사진](https://monorail.co.kr/승객용-모노레일-설치사진/view/6000): 이전 v83에서 확인한 제작사 외관 참고를 유지한다.
5. 기존 OSM 길·건물 평면, Copernicus GLO-30 지형 자료와 ODbL 표시는 유지한다.

위성영상과 사진의 촬영 시기가 다르다. 따라서 **2026년 현재 시설을 100% 동일하게 재현했다는 의미가 아니다.** 외관·시설 관계를 확인할 수 있는 자료 기반의 모델 보강이다.

## 추정과 한계

- 수관에 가린 계단 연결, 실측 없는 폭·난간·아치·차량·승강장 덮개 치수는 추정이다.
- 종단 높이는 기존 30m DSM을 참고해 보간하고 양 끝 승강장에 맞췄다. 중간부 토공·계단참은 모델 해석이다. 보행 바닥과 실제 표시 지형이 겹치는 곳만 지형을 낮춰 간섭을 해소했다.
- 모델 상부 53.6421m / 하부 19.2090m, 기준 표고 25.5m를 유지한다. 더한 79.1421m / 44.7090m는 기존 DSM 해석값이며 승강장 실측 높이가 아니다.
- 원자료 5m 위치 정확도와 건물의 영상 기울어짐 때문에 OSM과 영상이 완전히 일치하지 않는다. OSM 모노레일을 무리하게 이동하지 않았다. 새 계단의 정상·전시동 연결부는 기존 모델의 보행 공간에 접속하도록 해석했다.
- 이전에 추정 배치한 나무 중 새 시설을 관통하는 것만 근·원거리 수관과 줄기를 함께 제거했다. 현장 식재 조사 결과가 아니다.
- 사진·위성영상의 픽셀은 모델 텍스처로 사용하지 않았다. 화강암은 기존 자체 절차적 재질을 재사용했다.

## 제작과 보존

`outputs/terrain-v89/bitgaram-park-glo30-terrain-v89d.blend`를 SHA-256으로 검증하며 보존했다. 새 수정본은 `outputs/bitgaram-v101/`에 저장하고, 반복 수정 시에도 v101·v101b 등의 파일을 덮어쓰지 않는다. 최종 파일명은 `sources/bitgaram/access-v101/build.json`에 기록한다.

v83 차량 Blender 원본은 현재 로컬에 없어 기존 배포 GLB를 별도 보존한 뒤 Blender에 가져와 `bitgaram-monorail-v101.blend`를 만들었다. 이 경위는 `cabin.json`에 기록했다. Three.js는 Blender가 내보낸 GLB를 표시하고 기존 모노레일 운행을 담당한다.

장소별 충돌 자료 `public/bitgaram-park-world.json`에 계단·계단참·연결 바닥과 난간·승강장 기둥을 함께 반영했다. 다른 장소의 `city-world.json`이나 `dasi-world.json`은 이 장소의 충돌 자료가 아니므로 수정하지 않는다.

전체 3D 지도도 동기화했다. 보존된 `bitgaram-overview-relief-v96b.blend`에서 이전 추정 직선 접근로의 면을 선택해 제거하고, 새 산책 모델의 시설과 차량을 같은 좌표로 추가한 `bitgaram-overview-v101b.blend`를 별도 저장했다. 새 시설을 관통하는 추정 수관 16개 구성요소와 근접한 줄기 구성요소도 정리했다. 기존 도시 GLB 두 조각의 정점·법선·색상 데이터는 바이트 단위로 보존하며, 새 시설은 압축 약 1.91MB의 별도 GLB로 내보내 함께 표시한다. 산책 화면과 지도에서 동일한 Blender 시설을 사용한다.

## 검증

검증 기록은 최종 모델을 내보낸 뒤 `verification.json`에 남긴다. 계단 양방향 이동 및 승강장 연결, GLB 바닥과 모든 새 계단 충돌 높이의 수직 광선 대조, 모노레일 왕복·미닫이문·승하차, 기존 보행 검사, 원본 보존과 gzip 일치를 확인한다. 사진의 일부만 닮도록 이동 검사를 약화하지 않는다.

최종 자동 검사: 필수 보행 74개 + 시설·지도·표고 관련 27개 = **101개 통과**. 지도 수관 정리 후 지도·표고 9개를 다시 실행해 통과했다. TypeScript와 production 빌드도 통과했다. 기존의 500kB 초과 JavaScript 청크 경고는 남는다.

공원 수정본은 `bitgaram-access-v101d.blend`다. 보존 대상 공원 메시 11,119개가 원본과 일치하고, 기존 추정 수목 30곳만 새 시설과의 간섭 때문에 정리했다. 계단의 최대 인접 단차는 덮개 내부 약 9.2cm, 외부 목재 계단 약 12.0cm다. 수치는 모델 검증값이며 실제 계단의 실측 제원이 아니다.
