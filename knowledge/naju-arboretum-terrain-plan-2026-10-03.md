# 나주수목원 산지 지형 분석과 구현 계획

작성: 2026-10-03 · 대상: 산포면 다도로 7, 전라남도 산림연구원 수목원·빛가람 치유의 숲

**현재의 평평한 지면을 입구에서 안쪽으로 완만하게 높아지는 정원 지형으로 바꾸고, 동쪽·남동쪽의 식산 산기슭과 능선이 이어져 보이도록 구성한다.** 기존 가로수길·꽃밭·놀이터의 배치를 출발점으로 삼아 높이를 조정한다. 산책 가능한 범위는 확인된 길을 중심으로 잡고, 먼 산지는 가벼운 경관 모델로 만든다.

이번 산출물은 지도·고도 분석과 제작 계획이다. 운영 GLB, Blender 수정본, 이동 코드, 배포는 변경하지 않았다.

## 1. 지도에서 확인한 지형

위성영상에 현재 모델의 OSM 지면 경계를 겹치고, 공개 고도 자료 179개 좌표를 조회했다. 넓은 범위 99점, 수목원 주변 격자·기존 명소·가로수길 축 80점이다. 아래 그림의 A/B/C는 제작을 설명하기 위한 구분이며 공식 시설 구역선은 아니다.

![위성영상, 현재 모델 경계, 고도 표본과 가로수길 단면](../outputs/arboretum-terrain-plan-2026-10-03/terrain-analysis.png)

| 구역 | 확인 내용 | 구현 방향 |
| --- | --- | --- |
| A. 입구·정원·가로수길 | 서쪽 도로에서 안쪽으로 이어지는 길과 정원. 기존 길 축의 DSM 표본은 안쪽으로 상승 | 큰 직선과 식재 배열을 유지하면서 길의 완만한 오르막과 옆 정원의 높이 차 반영 |
| B. 연구원 안쪽·산기슭 | 위성영상에서 정원·건물 뒤로 산림이 이어짐. 공식 안내에 치유센터와 여러 숲길이 존재 | 시설 주변의 비교적 평탄한 공간, 숲길 진입부와 주변 사면을 연결. 시설별 좌표·경사는 추가 대조 |
| C. 동쪽·남동쪽 산지 | 현재 지면 경계 바깥에서 지형이 크게 높아짐. 넓은 표본 중 높은 값은 현재 원점 동쪽 500m·남쪽 250m 부근에 나타남 | 실제 능선 방향을 따라 배경 지형 제작. 확인된 근거리 숲길만 별도 보행 범위에 포함 |

공식 소개는 시험포지와 생태숲을 함께 설명하며 **식산오름길·숲속사색길**을 명시한다. 공식 코스에는 치유센터–마중터–데크광장–숲속맨발길 등 연결 순서가 있어, 정원과 산림 구간을 함께 검토해야 한다. [산림연구원 소개](https://jnforest.jeonnam.go.kr/content/view.do?menuCd=FOREST003001001), [공식 코스 안내](https://jnforest.jeonnam.go.kr/content/view.do?menuCd=FOREST003001003).

2022년 현장 기사는 메타세쿼이아길을 완만한 오르막으로 묘사하고, 뒤편 식산으로 이어지는 등산로를 설명한다. 이 자료는 큰 지형 관계를 교차 확인하는 데 사용했다. 현재 시설물이나 세부 노면의 상태는 최신 사진을 우선해 대조한다. [한국일보 현장 기사, 2022-08-16](https://www.hankookilbo.com/news/article/A2022081610030000780).

### 고도 분석 수치와 해석 범위

| 분석 대상 | 이번 조회 결과 | 해석 |
| --- | --- | --- |
| 현재 OSM 지면 경계 안 90m 간격 표본 29점 | DSM 표면값 39–79m, 표본 범위 40m | 지형 변화가 있다는 예비 근거. 수목원 지면의 실측 최저·최고 높이는 아님 |
| 현재 시작 좌표 | DSM 표면값 약 40m | 지면 기준점을 정할 때 비교할 후보 |
| 기존 가로수길 축 약 430m, 11점 | 양끝 표면값 40→65m, 차이 +25m | 안쪽으로 올라가는 방향 확인. 최종 노면 높이·기울기는 별도 검증 |
| 같은 축의 양끝 평균 표면 기울기 | 약 5.81% | DSM 양끝 차이/수평거리로 계산한 참고값. 그대로 산책로에 적용하지 않음 |
| 원형 정원 / 놀이터 도착점 / 꽃정원 도착점 | 각각 DSM 약 45 / 46 / 48m | 기존 명소가 모두 같은 높이일 가능성을 재검토할 자료. 시설 바닥의 확정 고도는 아님 |
| 넓은 범위 99점, 250m 간격 | DSM 표면값 24–258m | 산지 방향과 큰 높이 변화 확인. 정상의 위치·높이를 확정하는 표본은 아님 |

자료는 **Open-Meteo가 제공하는 Copernicus GLO-90, 2021 release, 원자료 해상도 90m**다. Copernicus 자료는 나무·건물 등이 포함될 수 있는 **표면 높이 모델(DSM)**이다. 촘촘하게 다시 조회하거나 Blender의 격자를 5m로 만들어도 원자료의 정밀도가 높아지지는 않는다. [API 문서](https://open-meteo.com/en/docs/elevation-api), [Copernicus 자료 설명](https://registry.opendata.aws/copernicus-dem/).

위성영상 조회일은 2026-10-03이며 촬영일은 확인하지 못했다. 공식 방문 안내도는 시설 관계를 설명하는 그림이라 북쪽 방향·거리·고도를 그대로 읽을 수 없다. 안내도의 `199m` 같은 표기도 의미가 확인되기 전에는 해발고도로 사용하지 않는다.

## 2. 현재 모델에서 보완할 부분

현행 수목원은 지면과 대부분 산책로를 거의 같은 높이로 만들었다. 산림 배치와 수형은 고도화돼 있으나, 지형을 따라 오르는 느낌과 뒤편 산의 연결이 빠져 있다.

| 현재 파일·상태 | 지형 작업 때 필요한 변경 |
| --- | --- |
| `public/naju-arboretum-world.json`: 지면 `ground_campus_osm`의 윗면 0m | 높이가 있는 지형과 그 지형에 일치하는 보행 자료로 교체 |
| 현재 보행 경계 `[-530,160,-330,200]` | 정원·확인된 숲길의 실제 범위로 조정. 넓은 산 배경 범위와 분리 |
| `verticalNavigation: true` | 높이 이동은 이미 켜져 있지만, 경사진 지면을 읽는 자료·함수가 필요 |
| `lib/world.ts`: 바닥은 다각형마다 높이 하나 | 지형 삼각형 안의 높이를 계산하는 기능 추가. 기존 실내·데크의 평면 바닥 처리도 유지 |
| 시작점·명소 도착 높이 대부분 0m 또는 생략 | 모든 시작점·명소 도착점·NPC 발 위치를 새 지면 높이에 맞춰 갱신 |
| 나무의 가까운/먼 형상 쌍 | 양쪽에 같은 높이 이동을 적용해 전환 때 위치가 튀지 않도록 보존 |

제작 출발점은 `outputs/quality-v74/naju-arboretum-tree-crowns-v74.blend`다. 기존 원본과 사용자 수정본을 보존하고, 변경 전 객체 목록·배치·재질·LOD 짝을 기록한 뒤 새 이름의 작업본을 만든다. 더 최근의 사용자 수정본이 발견되면 그 파일을 우선한다. 과거 기본 생성 스크립트로 전체 모델을 다시 만들지 않는다.

## 3. 권장 제작 범위와 우선순위

**먼저 현재 산책 구역 안에서 경사를 정확히 느낄 수 있게 만들고, 그다음 산기슭과 능선을 연결한다.** 전체 식산 등산 코스 확장은 별도 범위로 둔다. 현재 요청에서 우선 필요한 결과는 산지에 자리 잡은 수목원의 공간감이다.

| 순서 | 작업 | 완료 시 보이는 차이 |
| --- | --- | --- |
| 1 | 가로수길·향나무길·정원 지면 높이 정리 | 입구에서 안쪽으로 갈수록 조금씩 올라가며 옆 구역도 같은 판처럼 보이지 않음 |
| 2 | 안쪽 시설과 숲 진입부 연결 | 건물 뒤·길 끝이 끊기지 않고 숲과 사면으로 이어짐 |
| 3 | 동·남동 산 능선과 골짜기 | 정원 뒤 하늘과 만나는 선이 실제 산지 형태에 가까워짐 |
| 4 | 확인된 근거리 숲길·데크 주변 | 근거가 확보된 구간에서 경사와 숲속 이동을 경험 |
| 5 | 흙·낙엽·풀·배수 흔적과 조명 | 지형이 단색 언덕처럼 보이지 않고 식재·시설과 자연스럽게 연결됨 |

## 4. 단계별 구현 방법

### 1단계 — 지형 자료 정렬과 확정

1. 현재 좌표 원점 `[35.00648,126.8256689]`, 동쪽 +X·남쪽 +Z 규칙을 유지한다. 자료마다 좌표계를 확인하고 원점·거리 단위를 맞춘다. Blender 높이축 Z와 GLB/Web 높이축 Y는 기존 내보내기 변환을 따른다.
2. 국토정보플랫폼에서 해당 도엽의 수치지형도·등고선 또는 지표 고도 자료를 확인한다. 자료 해상도·제작일·높이 기준·사용 조건을 기록한다. 공개 접근 가능 여부는 아직 확인하지 못했으므로 특정 5m 자료 확보를 전제로 일정을 잡지 않는다. [국토정보플랫폼](https://map.ngii.go.kr/).
3. 대안으로 공개 GLO-30 자료의 해당 타일을 검토한다. 이 자료도 DSM이므로 수관 높이 문제를 해결하는 지표 DEM으로 취급하지 않는다.
4. 입구·원옥제 주변·가로수길 끝·연구원 건물·치유센터 등 식별 가능한 기준점으로 위성영상과 공식 안내도를 정렬한다. 새 숲길과 시설의 위치는 이 대조가 끝난 뒤 확정한다.
5. 세 단면을 만든다: 주 가로수길 방향, 정원 구역을 가로지르는 방향, 안쪽에서 산기슭으로 이어지는 방향. 지표 자료와 사진에서 일치하는 경사·시설 바닥을 높이 기준으로 사용한다.

고도 자료가 부족한 작은 단차·절토면은 사진 근거와 함께 추정값으로 기록한다. 나무 높이를 빼기 위해 전 구역에 임의의 동일 보정치를 적용하지 않는다. 자료 사이 고도 기준이 다르면 먼저 기준을 통일한다.

**산출물:** 출처별 자료 목록, 좌표 정렬 결과, 세 단면, 확인/추정 구분을 포함한 지형 입력 자료.

### 2단계 — Blender 지면과 길 제작

- 입구 주변 높이를 로컬 기준 0m로 정한다. 원자료 높이의 공통 기준값을 빼되 구역 사이 높이 차는 유지하고, 수직 배율은 1배로 둔다.
- 정원·산책로는 필요한 구간에 2–5m 안팎의 메시 간격을 사용하고, 먼 산지는 20–50m 수준으로 단순화한다. 이는 제작 격자 간격이며 원자료 정확도와 구분해 기록한다.
- 길의 중심선과 양쪽 가장자리 높이를 함께 정해 옆 경사에 길이 잠기거나 공중에 뜨지 않게 한다. 현재 직선 가로수길의 선형은 유지하면서 종단 경사를 반영한다.
- 정원·꽃밭·놀이터·건물 주변은 시설에 맞는 평탄한 작은 면과 주변 완만한 경사를 연결한다. 기존 울타리와 꽃밭 경계는 이 면에 맞춰 조정한다.
- 연못은 한 수면 높이로 유지하고 주변 둑·지면을 연결한다. 데크·계단·옹벽·배수로는 위치와 형태를 확인한 구간부터 제작한다.
- 높이 자료만으로 숲길 위치를 생성하지 않는다. 숲길은 지도·사진에서 확인한 선형을 지형에 얹는다.

**산출물:** 새 Blender 지형 작업본, 회색 지면 GLB, 세 단면 대조 그림. 이 단계에서 곧은 길·주요 시설의 배치가 보존됐는지 먼저 확인한다.

### 3단계 — 기존 나무·꽃밭·시설 높이 맞춤

지형을 올리면 지면 위의 모든 객체도 함께 정리해야 한다. 한 번의 높이 적용으로 끝나는 객체와, 길이를 따라 모양을 바꿔야 하는 객체를 구분한다.

| 객체 | 적용 방식 |
| --- | --- |
| 나무·관목 | 뿌리 위치에서 지면 높이를 읽어 객체 전체 이동. 줄기는 중력 방향으로 세우고 수형·크기·회전 보존 |
| 가까운/먼 나무 쌍 | 같은 기준점과 높이 이동 사용. 서로 다른 높이로 보정되지 않도록 짝 검사 |
| 꽃·풀의 반복 배치 | 개별 식재 위치에서 높이 적용. 배치가 공유 메시라면 기존 인스턴스 구조 유지 |
| 긴 울타리·길·생울타리 | 구간을 나누어 양끝 높이를 맞춤. 한 객체의 중심 높이만 바꾸는 방식은 피함 |
| 건물·놀이터·데크 | 기초·바닥 면을 먼저 정하고 지형과 연결. 구조물 전체를 사면 각도로 기울이지 않음 |
| NPC·표지판·명소 도착점 | 동일한 지면 높이 자료로 발 위치·기둥 바닥·도착 높이 설정 |

**산출물:** 기존 객체 보존 검사, 지면 접점 검사, 입구·꽃밭·놀이터·안쪽 숲의 비교 렌더.

### 4단계 — 지형과 실제 보행 높이 연결

Blender에서 확정한 지면을 GLB와 보행 자료로 함께 내보낸다. 화면용 지면과 이동용 지면이 같은 높이를 사용해야 경사에서 발이 박히거나 떠오르지 않는다.

- `public/naju-arboretum-world.json`에 지형 높이 자료 참조·좌표 원점·격자 간격·범위·높이 기준을 추가한다. 높은 밀도의 자료는 별도 JSON으로 분리할 수 있다. 필드 이름은 구현 시 확정한다.
- `lib/terrain.ts`에 지면 높이 조회를 추가한다. 실제 GLB와 같은 삼각형 대각선 규칙으로 삼각형 안의 높이를 보간한다. 렌더 메시와 다른 보간 방식으로 중앙이 어긋나지 않게 한다.
- `lib/world.ts`의 보행은 기존 평면 바닥과 지형 바닥을 함께 처리한다. 지형의 유효 범위, 경사 한계, 계단 단차, 시설 충돌을 검사한다. 멀리 보이는 산이나 연못으로 진입하지 않도록 보행 가능 영역을 구분한다.
- `app/explorer.tsx`의 카메라는 지면 위 기존 눈높이를 유지한다. 시선은 사용자가 조작하고, 노면의 작은 요철로 화면이 기울거나 출렁이지 않게 한다.
- 시작·처음 위치·명소 이동·NPC 배치·표지판·자동 이동이 동일한 높이 조회를 사용하도록 연결한다. 저장된 이전 산책 위치도 유효 지면으로 복구한다.
- `lib/destinations.ts`의 전체 보기 카메라와 미니맵 범위를 함께 확인한다. 전체 보기의 중심은 수목원에 두고, 새 산 배경의 전체 바운딩 박스 때문에 정원이 지나치게 작아지지 않도록 한다.
- 시설물의 충돌 높이·경계와 필요한 문·통로 높이도 갱신한다. 긴 장애물은 구간별 바닥 높이에 맞춘다.
- 자료가 없는 영역에서 기본 높이 0으로 돌아가거나, 머리 위 데크로 갑자기 올라가는 동작을 방지한다. 실내와 데크는 기존 평면 높이 처리로 구분한다.

**산출물:** 지형과 일치하는 보행 JSON, 높이 조회·이동 처리, 경사 이동 검증. 다른 장소의 기존 이동에도 회귀 검사를 수행한다.

### 5단계 — 산 경관·재질·태블릿 성능

산림의 가까운 구간은 기존 나무 LOD를 활용하고, 먼 구간은 단순한 수관 군집과 지형 재질로 구성한다. 능선까지 가까운 나무 모델을 복제하지 않는다. 지형 색은 경사·토양·숲 구역에 따라 조절하고, 큰 무늬 반복이 눈에 띄지 않도록 한다.

다음 수치는 **초기 제작 예산 제안**이다. 실기기 측정 후 조정한다.

| 항목 | 제안 기준 |
| --- | --- |
| 새 지형 면 수 | 가까운 지면과 먼 산 합계 약 3만–6만 삼각형부터 시작 |
| 원거리 지형 | 별도 단순화 메시, 거리·시야에 따른 표시, 그림자 비용 제한 |
| 추가 전송량 | 지형·높이 자료 증가분 gzip 약 1–2MB 이내를 1차 목표로 설정 |
| 태블릿 산책 | 실제 Android 태블릿의 동일 위치·해상도에서 평균 프레임 시간 33.3ms 이하를 목표로 측정 |
| 검증 구간 | 가로수길, 꽃밭·놀이터, 안쪽 숲 진입부, 전체 보기 각각 60초 이상 |

현재 수목원 GLB gzip은 11,472,045바이트다. 기존 나무 형상과 공유 구조를 유지하고 지형 작업 때문에 크게 늘지 않게 관리한다. 이전 기록의 데스크톱 프레임 값은 Android 태블릿 결과로 사용하지 않는다. [기존 수형·성능 기록](naju-arboretum-tree-quality-2026-10-02.md).

## 5. 완료 판정과 검증

| 확인 항목 | 통과 기준 |
| --- | --- |
| 지도·사진 일치 | 세 단면과 주요 기준점에서 경사 방향·시설 높이 관계가 설명 가능. 확인값과 추정값 분리 |
| 모델 보존 | 기존 식재의 평면 위치·수형·재질과 가까운/먼 짝 유지. 필요한 지면 접점 조정만 기록 |
| 이동 | 입구→가로수길→꽃밭/놀이터→확인된 안쪽 연결부→복귀 과정에서 지면 관통·부유·갑작스러운 높이 이동 없음 |
| 카메라·도착 | 시작, 재입장, 이전 위치 복구, 처음 위치, 명소 이동 모두 노면 위 정상 눈높이 |
| 시설 접점 | 나무 뿌리·울타리·데크·건물 기초·NPC 발이 지면에 맞음. 연못 수면은 평탄 |
| 보행 범위 | 확인되지 않은 먼 산·급경사·연못으로 진입하지 않음 |
| 자동 검증 | `node --experimental-strip-types --test tests/world.test.mjs` 및 새 지형 보간·경사·경계·태블릿 입력 회귀 검사 |
| 성능·화면 | Android 가로 화면에서 동일 경로로 전후 측정. 다운로드 크기·콘솔 오류·로딩 재시도·LOD 전환 확인 |

첫 검토 결과물은 **회색 지형과 기존 배치가 함께 보이는 GLB, 위성 중첩 그림, 세 단면, 짧은 경사 산책 화면**으로 한다. 공간 형태를 맞춘 뒤 재질·숲 바닥 디테일을 마무리하는 순서가 적절하다.
