# 태블릿 UI 보완과 다음 제작 계획

2026-10-01. 현재 앱의 조작·화면 구성을 보완했다. Blender 원본, 모델 좌표와 충돌 정보는 변경하지 않았다.

## 구현한 보완

| 발견한 문제 | 수정 |
| --- | --- |
| 고정 최소 높이 때문에 작은 가로 화면이 잘림 | 100dvh, 안전 영역 여백, 짧은 화면 전용 배치 |
| 태블릿에서 키보드 안내만 노출 | 이동·시선 버튼 분리, 터치 안내, 설정에서 이동 버튼 표시 선택 |
| 세로에서도 좁은 산책 화면을 열게 됨 | 터치 기기 세로 화면은 회전 안내로 막고 이동 중지. 버튼을 누르면 전체 화면과 가로 잠금을 순서대로 요청 |
| 시작할 때 마우스가 잠겨 메뉴 접근이 어려움 | 드래그 시선 조작을 기본으로 사용 |
| 두 손가락 확대와 한 손가락 회전이 섞임 | 포인터별 제스처 추적. 이동 버튼은 시선 제스처에 포함하지 않음 |
| 큰 환영 카드·반복 감성 문구가 풍경을 가림 | 작은 시작 카드, 실제 장소 이름, 차분한 종이색과 녹색, 간결한 안내 |
| 빛가람 안내가 작은 가로 화면에서 세로로 밀림 | 지도와 목록을 두 열로 유지하고 목록만 스크롤 |
| 지도 비율에 따라 클릭 좌표가 어긋남 | SVG 좌표계로 클릭 변환, 지도 높이에 맞춘 비율 유지 |
| 지역 지도 높이·축척 표기가 실제 범위와 불일치 | 1000×400 좌표에 맞춤. 근거 없는 축척과 공통 출구 방향 표시 제거 |
| 장소 번호가 010, 011로 표기됨 | 10, 11로 교정 |
| 지도·안내창의 초점과 키보드 이동이 불명확 | 기본 dialog 사용, 탭 방향키 이동, 닫기·전체 화면 버튼 이름 제공 |
| 초기 순간 다른 장소가 먼저 뜸 | URL의 장소를 정한 뒤 해당 장면만 마운트 |
| 태블릿 고해상도 렌더 부담 | ‘편하게 걷기’ 픽셀 비율 1.1, ‘선명하게 보기’ 1.75 상한. 설정 저장 |
| 멈춘 조감도도 계속 GPU 렌더 | 카메라 변경 때만 다시 렌더. 숨겨진 탭 렌더 중지 |
| 위치가 그대로인데 지도 HUD 반복 갱신 | 같은 위치 상태 재사용, 지도 도형 계산 캐시 |
| 배포에 미사용 스타일과 읽기용 JS 포함 | 미사용 components 스타일 검색 제외, JS 압축. CSS 약 204→49KB, JS 약 2,080→888KB |

사진·실측으로 확인되지 않은 내부와 식재는 기존 ‘자료·제작 정보’에서 추정임을 유지한다. 전망실 파노라마의 AI 생성 여부도 숨기지 않는다. ‘AI 느낌 줄이기’는 가공 사실을 감추는 의미가 아니다.

## 가로 모드의 범위

자동 회전은 브라우저가 허용해야 가능하다. 지원 기기는 사용자 버튼을 누른 뒤 전체 화면과 screen.orientation.lock('landscape')를 요청한다. 미지원·거부 시 안내를 표시하며 기기를 가로로 돌릴 때까지 산책 화면은 사용되지 않는다. CSS로 화면만 억지로 회전하지 않는다.

iPad Safari 등에서는 직접 기기를 돌려야 할 수 있다. 회전 잠금이 켜져 있거나 분할 화면이 세로 비율이면 안내가 유지된다. 실제 Android/iPad 하드웨어의 방향 잠금은 아직 실기기 검증하지 않았다.

근거: [MDN 화면 방향 잠금](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock), [Pointer Events 두 손가락 확대](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events/Pinch_zoom_gestures).

## 검증

- TypeScript 검사 성공, 정적 프로덕션 빌드 성공.
- 전체 테스트 102개 통과. 이동·계단·문·배·지도 이동과 새 가로 잠금/제스처 검사 포함.
- 브라우저 화면 1280×720, 1024×768, 844×390 확인. 마지막 크기에서 이동·시선·하단 버튼 충돌을 찾아 수정.
- 터치 버튼은 실제 UI 설정으로 표시해 확인. 브라우저 크기 변경은 실기기 터치·OS 방향 잠금 검증을 대신하지 않는다.
- 장소 선택, 산책 시작, 도움말·화질 설정, 지역 지도와 장소 내부 지도 확인.
- 기존 18개 GLB gzip 복원이 원본과 일치하는 빌드 검사 유지.
- 모델 자체 용량을 줄인 작업은 아니다. 위 용량은 앱 코드·스타일 용량이다.

## 다음 제작 우선순위

현재 완료한 UI와 아래 모델 제작 계획을 구분한다. 아래 항목은 아직 새 모델로 제작한 결과가 아니다.

| 순서 | 작업 | 완료 판단 기준 |
| --- | --- | --- |
| 1 | 장소별 같은 시점의 실제 사진과 모델 비교 보드 | 지붕·창·보도·수목별 차이 표시 |
| 2 | 빛가람 반복 건물 입면 교정 | 블록별 실제 층수·지붕·창 비례를 출처와 함께 기록 |
| 3 | 수목원·드들강 수종별 실루엣·수피·수관 | 소나무/메타세쿼이아/활엽수 형태가 가까이서도 구별됨 |
| 4 | 식재 밀도와 빈 공간을 현장 사진에 맞춤 | 산책로와 잔디 빈자리 보존, 무작위 나무로 채우지 않음 |
| 5 | 꽃밭의 실제 구획·계절·식물 높이 | 동일 시기의 사진과 구획별 꽃 색·수형 비교 |
| 6 | 포장·난간·벽 재질 거칠기와 마감 | 과한 광택·반복 줄무늬 감소, 실물 비례 줄눈·경계석 |
| 7 | 호숫가·강변·숲 경계 연결 | 직사각형 패치·급격한 색 단차·떠 있는 식물 없음 |
| 8 | 실제 벤치·표지판·가로등 위치와 크기 | 눈높이 규모감과 통행 폭이 맞음 |
| 9 | 사진으로 검증 가능한 실내만 보강 | 임의 장식보다 문·창·계단부터 확인 |
| 10 | 전망실 실제 360도 파노라마 확보 | 권리·촬영 위치·방향 확인. 일반 촬영 영상을 360도 실사라고 표기하지 않음 |
| 11 | 태블릿 GPU별 LOD·그림자·텍스처 예산 측정 | Android/iPad에서 한전·수목원·빛가람 프레임 시간 측정 |
| 12 | 지도와 실제 보행 범위 표현 | 배경과 걸을 수 있는 길 구별 |
| 13 | 문·배·장소 이동 후 도착 시선 | 장애물·벽 안쪽을 보지 않고 다음 경로가 보임 |
| 14 | 현장 명칭과 표지판 글자 교정 | 실제 지명·글자 크기·방향, 추정 표지 구분 |
| 15 | 사용성 실기기 확인 | 회전 잠금/분할 화면/브라우저 바/두 손 조작/저전력 설정 점검 |

모델 수정은 사용자 .blend를 보존한 새 편집본에서 진행한다. 지형·벽·문 변경 시 world JSON도 갱신하고 이동 검사를 다시 실행한다. 출처와 추정은 knowledge/sources에 분리해 기록한다.
