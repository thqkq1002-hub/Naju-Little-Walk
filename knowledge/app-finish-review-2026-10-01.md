# 앱 마감 검토와 자연스러운 풍경 제작 기준

2026-10-01. 선행 태블릿 UI·공원 수관 작업을 이어 받아 앱의 대기·중단·복구 흐름을 보완했다. 이번 변경은 표시 코드와 UI이며 사용자 Blender 원본과 충돌 자료를 변경하지 않는다.

## 이번에 직접 수정한 부분

- 처음 세로로 접속한 터치 기기는 회전 안내부터 표시한다. 실제 입력 방식과 화면 방향을 확인하고 가로 화면이 된 뒤 장소의 3D 코드를 요청한다.
- 한 번 연 장면은 다시 세로로 돌려도 보존한다. 이동은 멈추고 화면은 잠기며, 가로로 돌아오면 같은 장면에서 이어 갈 수 있다.
- 조감·일시정지 화면은 변경 시에만 렌더링한다. 가려진 탭·세로 안내·GPU 연결 중단 중에는 GPU 렌더를 하지 않는다. 이동 중에는 계속 갱신해 보행·배 동작을 유지한다.
- GPU 연결이 복원되면 기존 장면과 위치에서 다시 표시한다. 직접 재시도할 경우에는 출발 위치에서 새로 준비한다. 승선 중에도 복구 안내가 보인다.
- 모델 로딩 실패 시 페이지 전체 새로고침 없이 해당 장면을 다시 준비하거나 다른 장소를 고를 수 있다. 3D 코드 자체를 불러오지 못할 때도 흰 화면 대신 안내를 표시한다.
- 실제 터치 기기 여부와 이동 버튼 표시 설정을 구분했다. 버튼 표시를 바꿔도 기기용 조작 설명은 바뀌지 않는다.
- 초기 회전·기본 UI와 장소별 3D 코드를 분리했다. 운영 v57의 최초 JS 약 891KB에서 209KB로 나뉘었으며, 3D 화면을 열면 나머지도 내려받는다. 전체 JS 총량 감소라고 주장하지 않는다.

| 순서 | 현재 어색함 | 구체적인 작업 | 판단 기준 |

| 5 | 마감이 평평하거나 과하게 반짝임 | 포장·난간·벽의 거칠기, 줄눈 크기, 사용 흔적을 제한적으로 보완 | 실제 물체 크기에 맞는 질감, 원거리 잡음·모아레 감소 |
| 6 | 화면과 안내문이 장소마다 같은 인상 | 현장 이름·출입 방향·시설 기능을 중심으로 짧은 안내 | 필요한 정보가 먼저 보이고 풍경을 가리지 않음 |

이 목록은 새 모델 제작의 후속 계획이다. 이번 UI 수정으로 건물·수목원·드들강 모델을 모두 실측 수준으로 완성했다고 주장하지 않는다. 임의로 공간을 꽉 채우거나 색·회전을 무작위로 바꾸는 것은 정확도 개선의 대체가 아니다.

## 완료 판단과 남은 확인

- 앱 기능: 장소 선택 → 조감 회전/확대 → 보행 → 일시정지/안내 → 다른 장소 이동, 실패 후 재시도까지 확인한다.
- 태블릿 배치: 1024×768과 짧은 가로 844×390에서 안내창·이동 버튼·장소 푯말을 확인한다.
- 자동 회전: 지원 기기는 사용자 버튼 후 전체 화면과 가로 잠금을 요청한다. 미지원 브라우저는 직접 회전 안내를 유지한다. 모든 OS의 강제 회전을 웹 앱이 보장할 수는 없다. [MDN ScreenOrientation.lock](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock).
- 실제 Android/iPad의 OS 회전 잠금·분할 화면·두 손 조작·GPU 복구는 실기기 확인이 필요하다. 데스크톱 브라우저의 크기 변경과 단위 검사를 실기기 검증으로 표기하지 않는다.
- 전체 계획의 상태는 [QUALITY_UPGRADE_PLAN.md](QUALITY_UPGRADE_PLAN.md), 선행 UI 결과는 [tablet-ui-completion-2026-10-01.md](tablet-ui-completion-2026-10-01.md)에서 유지한다.

## 검증 기록

- 사용자 주 대상은 **안드로이드 태블릿**이다. 회전 안내·전체 화면·가로 잠금 요청·기본 균형 화질을 이 사용 방식에 맞췄다.
- 전체 검사 107개 통과. 세로/가려짐/GPU 중단 시 변경 보존, 정지 시 렌더 중지, 이동 중 연속 렌더 검사 3개를 추가했다. 보행·문·배·기존 모델 검사도 포함한다.
- TypeScript 검사와 정적 프로덕션 빌드 성공. 최초 JS 208.90KB(gzip 67.24KB), 공유 3D/지도 625.43KB, 산책 32.29KB, 빛가람 선택 28.67KB, CSS 49.75KB. 전체 JS가 500KB 미만이라는 뜻은 아니다.
- 1024×768과 844×390에서 보행, 이동/시선 버튼, 안내창을 확인했다. 844×390에서 안내 내용만 스크롤되고 닫기 버튼은 상단에 남는다.
- 공원 조감도 렌더 프레임 카운터가 두 관찰에서 3→3, 일시정지 상태도 1071→1071로 유지됐다. 보행에서는 카운터가 계속 증가한다. 실기기 배터리 절감률을 측정한 결과는 아니다.
- 정상 공원 화면의 콘솔 오류는 없었다. GPU 연결의 실제 단절·복원과 OS 방향 잠금은 실기기 미검증이다.
- 검증용 로컬 서버에서 공원 모델의 첫 요청만 503으로 실패시켰다. 실제 ‘출발 위치에서 다시 불러오기’ 버튼으로 재시도한 뒤 오류 카드가 사라지고 산책 시작·확대 버튼이 활성화되는 것을 확인했다. 원본 모델 파일은 수정하지 않았다.
- 추가로 1280×800에서도 조감·메뉴·시작 버튼을 확인했다. 이는 안드로이드 태블릿 크기의 데스크톱 모의 검증이며 실제 Android 하드웨어 확인은 아니다.
