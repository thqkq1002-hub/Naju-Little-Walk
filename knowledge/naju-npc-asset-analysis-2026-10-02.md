## 1. 핵심 판단

**제공 자료를 기준으로 지역별 안내 캐릭터를 만드는 작업은 가능하다. 다만 현재 자료는 2D 캐릭터 매뉴얼이므로, Blender에서 세 캐릭터를 입체로 제작하고 선생님 캐릭터 한 명을 새로 설계해야 한다.**

기본형, 흑백 표현, 그리드, 여러 응용 장면이 있어 얼굴·색·의상·소품을 맞추는 데 유용하다. 반면 측면·뒷면 도면, 3D 메시, 뼈대, 실제 움직임 파일은 압축되지 않은 자료에서 확인되지 않았다. 앞모습을 닮게 만드는 기준은 충분하지만, 뒤통수·등·옷 뒷면·몸통 두께는 별도 설계가 필요하다.

현재 앱은 Blender GLB를 표시하고 정적인 건물·식물을 최적화하는 구조다. 움직이는 NPC와 대화 기능은 따로 연결해야 한다. 특히 기존 정적 모델 합치기와 한전의 행렬·그림자 고정 최적화에 NPC를 그대로 넣으면 동작이 잘못되거나 그림자가 남을 수 있다.

추천 진행은 **배돌이 한 명으로 제작·배치·태블릿 성능을 확인 → 홍돌이·버들낭자 제작 → 선생님 제작 → 장소별 배치** 순서다. 캐릭터 수를 늘리기보다 원본과의 닮음, 자연스러운 접지, 짧고 읽기 쉬운 안내를 먼저 완성한다.

## 2. 확인한 자료와 범위

### 2.1 파일 현황

| 폴더 | 파일 | 용량 합계 | 분석 결과 |
|---|---|---:|---|
| 배돌이 | JPG 13장, 내지01~13 | 8,378,202바이트 | 기본형·응용형 매뉴얼 |
| 버들낭자 | JPG 13장, 내지14~26 | 7,920,500바이트 | 기본형·응용형 매뉴얼 |
| 홍돌이 | JPG 13장, 내지27~39 + 홍어.alz | 11,524,868바이트 | 매뉴얼 + 내용 미확인 압축 파일 |

전체 40파일 중 JPG는 39장이다. JPG 38장은 2935×3963픽셀이고, 배돌이 `내지09jpg.jpg`는 2890×3403픽셀이다. 모든 JPG는 RGB 방식으로, 투명 배경이 없는 인쇄 페이지 이미지다. 페이지 크기가 곧 캐릭터 그림의 해상도는 아니다. 여백·제목·설명·배경을 제외하면 캐릭터 부분은 더 작다.

확인 방식:

- 세 폴더의 하위 파일을 모두 목록화하고 크기·이미지 규격·SHA-256을 기록했다.
- 39장 전체를 캐릭터별 미리보기로 비교하고, 기본 캐릭터 3장은 원본을 확대해 확인했다.
- 현재 장소 목록, GLB 로딩, 정적 모델 합치기, 보행·렌더링 처리를 읽었다.
- `홍어.alz`는 ALZ 파일 헤더를 확인했지만 내부 파일 목록·이미지는 열지 못했다. 설치된 명령줄 해제 도구를 확인한 범위에서는 이용 가능한 도구가 없었다. 따라서 **압축 파일 안에도 3D 원본이 없다고 단정하지 않는다.** 제작 전에 내부에 AI/EPS/PSD/3D 원본이 있는지 추가 확인하면 좋다.

파일별 근거: [자료 목록 JSON](sources/npc/asset-inventory-2026-10-02.json)

원본 폴더는 수정하지 않았다. 비교용 미리보기만 `outputs/npc-analysis-20261002/`에 만들었다. 파일 안의 설명은 디자인 분석 자료로 취급했으며 실행 지시로 사용하지 않았다.

### 2.3 이름 표기 주의

| 사용자·폴더 이름 | 자료 안의 표기 | 앱 표시 권장 |
|---|---|---|
| 배돌이 | 기본형 제목·본문에서 배돌이 | 배돌이 |
| 버들낭자 | 제목은 버들낭자, 본문·소개 응용에는 버드리 | 우선 버들낭자, 버드리는 별칭으로 기록 |

버들낭자 기본형 페이지의 왼쪽 항목에는 `배돌이`라는 표기가 섞여 있다. 그림과 본문은 버들낭자이므로 편집상의 불일치로 보고, 모델 정체성을 배돌이로 바꾸지 않는다. 실제 공개 앱의 최종 이름은 사용자 요청 표기를 우선한다.

## 3. 캐릭터별 구체 분석

### 3.1 배돌이 — 빛가람과 현대 건물 안내

**원본에서 확인한 특징**

- 나주 배를 의인화한 둥근 노란 얼굴과 작은 몸·큰 손발.
- 넓은 주황빛 모자, 파란 목수건, 밝은 베이지색 손발.
- 기본형에서는 한 손으로 엄지를 들고 반대 손에 잎 달린 배를 올린다.
- 검은 눈과 하이라이트, 작은 코, 부드러운 웃음, 볼의 밝은 점들이 인상을 만든다.
- 환영, 주차 안내, 꽃밭, 깃발을 든 장면 등 용도별 응용형이 있다.

**보존할 부분**: 모자 챙과 얼굴의 비율, 배 형태의 얼굴, 파란 목수건, 작은 몸에 비해 큰 손발, 배 소품. 현대 건물에 배치한다고 정장·안전모·로봇 모습으로 바꾸면 원본과 멀어진다.

**3D 설계가 필요한 부분**: 모자의 뒤쪽 형태, 몸통과 얼굴 연결, 목수건 매듭 뒤쪽, 손바닥의 배를 안정적으로 고정할 위치. 뛰는 듯한 기본 그림을 그대로 정지 자세로 쓰면 떠 있는 인상을 줄 수 있으므로, 원본의 활발함을 유지하면서 발이 바닥에 닿는 대기 자세를 따로 만든다.

**제안 동작**: 작은 호흡, 눈 깜박임, 배를 든 손은 유지하고 다른 손으로 인사·방향 안내. 깃발·주차 표지 등 모든 응용 소품을 기본 모델에 붙일 필요는 없다.

### 3.2 버들낭자 — 전통 건물과 복암리 안내

**원본에서 확인한 특징**

- 검은 올림머리와 길게 내려오는 머리카락, 금색 머리 장식과 귀걸이.
- 분홍 상의, 푸른 보라색의 넓고 긴 치마, 짙은 청보라색 장식 띠.
- 띠와 소매 끝의 곡선 무늬, 밝은 안쪽 깃, 차분한 표정.
- 팔을 펼쳐 맞이하는 기본형과 버드나무·꽃·홍보 장면의 응용형.
- 제공 본문은 장화왕후 오씨를 모티브로 설명한다. 이는 자료의 설정이며 별도 역사 검증을 수행한 것은 아니다.

**보존할 부분**: 머리 윤곽, 길게 떨어지는 치마의 형태, 분홍·보라·청색의 구분, 장식 띠와 차분한 얼굴. 일반적인 한복 캐릭터로 대체하면 이 자료의 특징이 사라진다.

**3D 설계가 필요한 부분**: 올림머리 뒤 구조와 장식, 뒷깃·허리·치마 뒤 주름, 소매와 몸통 사이의 공간. 원본에 없는 뒷면 무늬는 확인된 사실로 표시하지 않는다.

**제안 동작**: 작은 고개 인사, 한 손으로 장소 안내, 자연스러운 눈 깜박임. 첫 구현에서는 옷감 시뮬레이션을 사용하지 않고 제한된 뼈대 동작으로 소매·치마를 움직인다. 손과 소매, 치마와 발이 겹치는지 근접 화면에서 확인한다.

### 3.3 홍돌이 — 영산포 안내

**원본에서 확인한 특징**

- 위로 뾰족하고 양옆이 넓어지는 홍어 형태의 흰 몸.
- 짙은 파란 외곽선, 파란 신발, 흰 장갑 같은 큰 손.
- 큰 눈·윙크·웃는 입과 주황빛 입 안, 옅은 분홍 볼.
- 몸 뒤로 뻗는 가느다란 꼬리, 환영·물놀이·축제·공부 장면 등 응용형.

**보존할 부분**: 홍어 특유의 넓은 몸통 실루엣, 흰 몸과 파란 강조색, 눈·입·손발의 비율. 삼각형 사람 머리나 둥근 유령 형태로 단순화하면 알아보기 어렵다.

**3D 설계가 필요한 부분**: 몸의 두께와 등 곡면, 뒤쪽 꼬리 연결, 팔과 넓은 몸통의 연결 방식. 정면은 자료를 따르고 측면·후면은 입체화를 위한 설계로 구분한다.

**제안 동작**: 인사·윙크·방향 안내. 물놀이 장면은 표현 참고이며 NPC를 강 위에 띄우거나 배에 자동 탑승시키라는 요청으로 해석하지 않는다. 첫 배치는 육지의 안내 위치가 적절하다.

### 3.4 다시초등학교 선생님 — 신규 캐릭터

제공 폴더에 선생님 원본은 없다. 기존 세 캐릭터와 같은 장면에서 어울릴 **친근한 일반 교사 한 명**을 새로 디자인한다.

제안 기준은 단정한 현대 복장, 읽기 쉬운 얼굴, 자연스럽게 서 있는 자세와 작은 책 또는 출석부다. 특정 실존 교사의 얼굴·이름을 사용하지 않는다. 성별·연령·안경 여부는 캡처에 정해져 있지 않으므로 최종 디자인 선택 사항으로 남긴다.

필수 동작은 대기·인사·학교 방향 안내이며, 학생 군중이나 수업 시뮬레이션은 이번 배치안의 필수 범위가 아니다. 학교 정문 안쪽의 보행 공간 또는 현관 옆에 한 명을 배치하는 안을 우선 검토한다.

## 4. 요청 배치안과 현재 앱의 연결

아래 캐릭터의 지역 배정은 사용자 캡처에서 가져왔다. 구체 위치·개수·안내 내용은 제작 제안이며 아직 좌표를 확정하지 않았다.

| 요청 지역 | 현재 장소 ID | 캐릭터 | 1차 배치 제안 |
|---|---|---|---|
| 영산포 | `yeongsanpo` | 홍돌이 | 홍어거리의 접근 가능한 안내 지점 1곳 |
| 나주시내 전통 건물 | `geumseonggwan` | 버들낭자 | 금성관 진입부 옆, 문과 보행로를 비켜선 위치 |
| 복암리 고분 | `bogam` | 버들낭자 | 고분군 진입 산책로 옆; 봉분 위는 제외 |
| 빛가람 공원·전망대 주변 | `bitgaram-park` | 배돌이 | 입구 또는 안내도 주변의 평탄한 공간 |
| 한국전력 본사 | `bitgaram-kepco` | 배돌이 | 앞마당·로비 중 대표 안내 지점 1곳 |
| KENTECH | `bitgaram-kentech` | 배돌이 | 정문 또는 1층 안내 공간 중 1곳 |
| 다시초등학교 | `dasi` | 신규 선생님 | 정문 안쪽 또는 본관 입구 옆 1곳 |

1차 안은 **캐릭터 원형 4종, 장소별 배치 7개**다. 같은 버들낭자·배돌이를 여러 장소에서 사용해도 모델 원형을 별도로 다시 만들 필요는 없다. 이는 제안 수량이며 사용자가 7개로 지정한 것은 아니다.

`bitgaram`은 장소 선택용 화면이며 공원 모델을 공유한다. 안내 화면과 공원에 중복 캐릭터를 올리기보다 공원 산책에 들어갔을 때 보이도록 하는 편이 자연스럽다.

추가 실내 후보인 `yeongsanpo-history`, `yeongsanpo-literature`, `bogam-museum`, `bitgaram-observatory`는 1차 배치 확정 범위에 넣지 않았다. 특히 전망실은 이전에 내부를 비우고 창밖 풍경을 우선하자는 요청이 있었으므로 자동으로 NPC를 추가하지 않는다. 수목원·드들강은 이번 캡처에서 캐릭터가 지정되지 않았다.

실제 지도에 NPC 위치가 있다는 뜻은 아니다. **캐릭터와 배치 위치는 앱의 창작 안내 요소**로 기록한다.

## 5. 기존 앱에 연결할 때 필요한 작업

### 5.1 현재 확인된 구조

- `lib/destinations.ts`: 장소와 GLB·월드 JSON을 연결한다.
- `app/explorer.tsx`: 장소 GLB 로딩, 보행·카메라, 그림자, 화면 대기·정지·정리를 담당한다. 확인한 코드에 NPC 관리나 `AnimationMixer` 연결은 없다.
- `lib/static-scene.ts`: 같은 재질의 정적 메시를 합친다. 뼈대 메시와 표정 변형 메시는 제외하지만, 일반 메시로 된 움직이는 소품까지 자동으로 보존하는 구조는 아니다.
- 한전 등 최적화 대상 장면은 모델의 `matrixAutoUpdate`와 그림자 자동 갱신을 끈다.
- 렌더링은 산책·화면 상태에 맞춰 제한된다. NPC가 추가되어도 전체 보기·일시정지·숨김 탭에서 무조건 계속 움직이게 만들면 기존 절전 효과가 줄어든다.

### 5.2 권장 구성 — 아직 구현하지 않은 설계

**건물 GLB와 NPC GLB를 분리한다.** Blender에서 만든 캐릭터를 별도 GLB로 내보내고, 기존 정적 장면의 합치기와 행렬 고정을 마친 뒤 별도의 NPC 그룹에 추가한다. 이렇게 하면 캐릭터 수정 때문에 대형 도시 모델을 다시 내려받는 일을 줄이고, 손·소품의 동작이 정적 메시로 합쳐지는 문제를 피할 수 있다.

장소별 설정에는 캐릭터 ID, 위치, 바닥 높이, 바라보는 방향, 크기, 안내 제목·문구, 상호작용 거리만 둔다. 예시 파일명은 `public/npc-placements.json`, 모델 경로는 `public/models/npc/*.glb`로 제안한다. 현재 이 파일이나 기능이 존재하는 것은 아니다.

애니메이션은 가까운 NPC만 갱신하고, 숨김 탭·일시정지·대화창에서는 불필요한 갱신을 멈춘다. 이동 가능한 NPC가 아니라 정해진 자리의 안내 NPC로 시작하면 길찾기와 움직이는 충돌체 구현을 줄일 수 있다.

한전에서 움직이는 NPC의 실시간 그림자를 기존 고정 그림자맵에 그대로 추가하면 잔상이 남을 수 있다. 1차에는 얇은 접지 그림자를 사용하고, 필요한 경우에만 그림자 갱신 비용을 측정해 추가한다.

모델·텍스처를 캐릭터끼리 재사용할 경우 장면 전환 시 공유 자원을 중복 해제하지 않도록 별도 소유·정리 규칙이 필요하다. 로딩 취소, 애니메이션 정리, 이벤트 해제도 NPC 추가 범위에 포함한다.

### 5.3 상호작용 제안

첫 버전은 캐릭터 이름과 짧은 장소 안내를 보여 주는 방식이 적절하다. 사용자가 가까이 다가가 **‘이야기 듣기’**를 누르면 안내창을 열고 이동 입력을 멈춘다. 안내창을 닫으면 원래 산책으로 돌아간다. 접근할 때마다 자동으로 창을 열지 않는다.

태블릿에서는 이름표·대화 버튼이 이동 패드, 시선 버튼, 미니맵과 겹치지 않게 배치한다. 키보드 사용자는 같은 기능을 명시된 키와 닫기 동작으로 사용할 수 있게 한다. 대화창 자체는 읽기 쉬운 HTML UI로 처리하는 안을 권장한다.

음성·생성형 AI 대화·퀘스트는 사용자 캡처에 없는 추가 기능이다. 고정된 짧은 안내만으로 먼저 완성하고, 필요해질 때 별도 범위로 정한다.

## 6. 원본과 닮게 제작하는 기준

| 항목 | 제작 원칙 | 확인 방법 |
|---|---|---|
| 얼굴·실루엣 | 컬러 기본형을 최우선 기준으로 사용 | Blender 정면 렌더와 기본형을 같은 크기로 비교 |
| 색 | JPEG의 조명·압축 오차를 고려해 기본형의 대표색부터 맞춤 | 동일한 중립 조명에서 비교; 공식 색상 번호 확인 전에는 추정색으로 기록 |
| 측면·후면 | 앞모습을 설명할 수 있는 자연스러운 입체 형태로 설계 | 정면·측면·후면·사선 렌더를 한 번에 검토 |
| 의상·장식 | 원본의 모자·목수건·한복 띠·머리 장식을 유지 | 확대 화면에서 누락·뒤틀림 확인 |
| 표정 | 눈과 입의 모양을 먼저 맞춘 뒤 필요한 표정만 추가 | 대기·인사·안내 장면 비교 |
| 접지 | 발·치마·바닥 사이가 뜨거나 뚫리지 않게 설정 | 실제 앱 보행 높이에서 측면·근접 확인 |
| 크기 | 건물·사람 시점과 어울리는 크기를 설계 | 문·난간·카메라 눈높이와 비교; 자료의 실측치로 주장하지 않음 |

강한 금속 광택, 과도한 볼륨, 반짝이는 장난감 재질을 일괄 적용하지 않는다. 기본형의 부드러운 색과 읽기 쉬운 얼굴을 유지한다. 반대로 검은 외곽선을 입체 전체에 무조건 두껍게 씌우면 주변 건물·식물과 분리되어 보일 수 있어 가까운 실제 장면에서 조절한다.

JPG 전체 페이지를 캐릭터 표면에 붙이는 방식은 사용하지 않는다. 페이지의 흰 여백·문구·그림자·풍경이 함께 따라오기 때문이다. 기본 그림은 디자인 기준으로 사용하고, 3D 표면용 색·얼굴·무늬는 별도로 정리한다. 원본 AI/EPS/PSD가 압축 파일 등에 있으면 특히 한복 무늬와 얼굴을 더 깨끗하게 제작할 수 있다.

## 7. 성능 목표와 제작 순서

### 7.1 태블릿용 초기 예산

아래 수치는 제작을 시작하기 위한 **제안 예산**이며 실제 기기에서 측정한 결과나 보장값은 아니다. 가까운 얼굴이 망가진다면 재질·동시 표시 수와 함께 조정한다.

| 항목 | 초기 목표 |
|---|---|
| 배돌이·홍돌이 근접 모델 | 각 8천~1만5천 삼각형 이내를 우선 검토 |
| 버들낭자·선생님 근접 모델 | 각 1만2천~2만5천 삼각형 이내를 우선 검토 |
| 중거리 모델 | 원본의 주요 윤곽을 유지하며 약 2천~5천 삼각형 |
| 재질 | 캐릭터당 2~4개 안팎; 작은 부품마다 재질을 나누지 않음 |
| 텍스처 | 기본 1024px, 얼굴·한복 무늬가 부족할 때 필요한 것만 2048px 검토 |
| 초기 배치 | 한 장소에 대표 NPC 1명 |
| 애니메이션 | 대기·인사·방향 안내 3종부터 시작 |
| 실시간 비용 | 물리 옷감·머리카락, 여러 투명 겹, 상시 실시간 그림자는 초기 제외 |

모델은 현재 장소에서 필요한 캐릭터만 불러오고, 멀리 있거나 화면 밖에 있는 NPC는 갱신을 제한한다. GPU 메모리는 다운로드 용량만으로 판단하지 않고 텍스처와 그림자까지 확인한다. 정확한 안드로이드 태블릿 모델이 아직 지정되지 않아 실제 FPS는 미확인이다.

### 7.2 실행 단계와 완료 조건

| 단계 | 작업 | 완료 조건 |
|---|---|---|
| 1. 기준 확정 | 압축 내부 확인, 기본형·이름·색 기준, 뒷면 설계 구분 | 원본/설계/미확인 항목이 나뉜 기준표 |
| 2. 배돌이 시제품 | Blender 모델·뼈대·3동작·GLB 제작 | 정면 유사도와 측면·후면·접지 확인 |
| 3. 앱 시제품 | 공원 한 곳에 배치, 안내창·정지·정리 연결 | 태블릿 버튼 충돌과 정적 최적화 간섭 없음 |
| 4. 기존 캐릭터 확장 | 홍돌이·버들낭자 제작 | 기본형 특징 유지, 소품·의상 동작 정상 |
| 5. 선생님 신규 제작 | 앞·옆·뒤 디자인 및 모델 제작 | 친근한 일반 교사, 기존 장면과 스타일 조화 |
| 6. 지역 배치 | 제안한 7개 지점의 실제 보행 위치 확인 | 문·이동 경로·포털을 막지 않음 |
| 7. 최종 검증 | 근접·원경·대화·장소 전환·숨김·복귀·기기 확인 | 모델 누락·입력 먹통·누적 자원 증가 없음 |

NPC에 물리적 충돌을 추가하면 해당 장소가 실제로 사용하는 월드 JSON에도 반영한다. 현재 다시초등학교의 연결 월드는 `dasi-neighborhood-world.json`이므로 기본 파일명만 보고 다른 JSON을 고치지 않는다. 이동 기능이 바뀌면 프로젝트 지침의 `node --experimental-strip-types --test tests/world.test.mjs`를 실행한다.

대화창과 장소 배치 기능은 그에 맞는 동작 검증을 추가한다. Blender 내부에서 정상이어도 웹의 GLB에서 같은 재질·소품·애니메이션이 보이는지 확인해야 완료로 본다.

## 8. 남은 확인 사항과 최종 산출물

현재 부족한 자료는 압축 파일 내부 원본, 측면·후면 기준, 정확한 색상 규격, 선생님 디자인, 장소별 최종 좌표·안내 문구다. 이 중 앞모습 모델링을 시작할 수 없는 수준의 부족은 아니지만, 정밀한 3D 최종본을 원본과 일치한다고 표현하기 전에는 설계한 부분을 분명히 해야 한다.

이번 보고서에 포함한 지역 배정은 사용자 캡처를 따른다. 자료 본문의 역사 설정·홍보 문구를 앱의 사실 안내로 그대로 옮기지 않고, 장소 안내 문구를 작성할 때 별도로 검증한다. 자료 자체에는 입체화·수정·공개 배포의 조건을 확정할 정보가 확인되지 않았으므로 제작 프로젝트의 자료 출처 기록과 지도 ODbL 표시는 구분해 유지한다.

후속 제작 산출물은 캐릭터별 `.blend` 원본, 웹용 GLB, 정면·측면·후면 렌더, 3종 동작, 장소별 배치 데이터, 짧은 안내 콘텐츠, 기기 검증 기록으로 구성한다. 사용자 원본 파일을 덮어쓰지 않고 각 캐릭터의 새 작업본과 수정 이력을 보존한다.

**권장 첫 제작 단위: 배돌이 한 명 + 공원 안내 지점 한 곳 + 인사·안내 동작 + 짧은 안내창.** 이 한 묶음의 닮음과 태블릿 동작을 먼저 확인하면 나머지 캐릭터·지역을 같은 기준으로 확장할 수 있다.
